**mapcv turns a region and polygon labels into a ready-to-train semantic-segmentation dataset.** You describe *where* (a longitude/latitude box), *what imagery* (XYZ map tiles or a Sentinel-2 L2A product) and, optionally, *what to label* (a GeoJSON, KML, GeoPackage, Shapefile or GeoParquet file). mapcv fetches the imagery, burns the polygons into masks on exactly the same pixel grid, cuts fixed-size patches, and writes them with a manifest and leakage-safe train/val/test splits.

## Why it exists

Building a segmentation dataset from map imagery usually means stitching tiles by hand, fighting coordinate systems, installing GDAL, and writing a one-off split script that quietly leaks neighbouring pixels between train and test. mapcv is a **data-creation-first** tool: one YAML file, three commands, and the result is plain files on disk.

- **No GDAL.** The core is Rust (tile math, tile fetching, rasterizing, patch sampling and encoding) behind a small Python layer. `pip install mapcv` is the whole setup for XYZ imagery.
- **Correct by default.** Labels are reprojected into the imagery's own CRS, class IDs are stable across files, and the default split keeps spatially close patches together.
- **Honest estimates.** `mapcv plan` tells you how many tiles, patches, megabytes and how much memory a run needs before anything is downloaded.
- **Resumable.** The manifest is saved after every chunk. If a run stops, the same command continues it.

## Who it is for

- Computer-vision and ML researchers who need a segmentation dataset for a specific place, without becoming GIS specialists.
- Remote-sensing practitioners who want multispectral Sentinel-2 patches as plain `float32` arrays.
- Anyone teaching or benchmarking who needs a dataset that can be regenerated from a config file.

## What you get

| Output | What it is |
| --- | --- |
| `Images/patch_0000000.png` | RGB patch from XYZ tiles (`.jpg` optional), or a bands-first `float32` `.npy` for Sentinel-2 |
| `Masks/patch_0000000.png` | `uint8` mask with the same name: `0` = background, `1…` = class IDs, `255` = no imagery (ignore) |
| `manifest.json` | Source, bands, CRS, affine transform, class map, sampler settings and per-patch statistics |
| `splits/train.txt`, `val.txt`, `test.txt` | One image filename per line |
| `splits/<percent>/labeled.txt` | Optional labeled/unlabeled subsets of `train` for semi-supervised learning |

With `task: detection`, each label feature becomes a box instead: COCO JSON per split, YOLO label files and an Ultralytics `dataset.yaml` replace the masks (see [Object detection datasets](/mapcv/tutorials/object-detection/)). With `task: instance`, each feature becomes its own binary mask instead: COCO JSON per split with RLE masks, and optionally a 16-bit instance-ID PNG per patch (see [Instance segmentation datasets](/mapcv/tutorials/instance-segmentation/)).

Details: [Dataset format](/mapcv/reference/dataset-format/).

## What mapcv does not do

mapcv 0.2 deliberately keeps a narrow scope. It does **not** search catalogues (STAC), mosaic several scenes, mask clouds, write GeoTIFFs, connect to Google Earth Engine, or authenticate to private buckets. It reads one Sentinel-2 product per run, and XYZ sources must serve standard 256 × 256 tiles.

<Aside type="caution" title="Imagery rights are yours to check">
mapcv processes imagery; it does not grant you the right to download, cache, train on or share it. Read [Providers & licensing](/mapcv/project/providers/) before you generate a dataset from someone else's tiles.
</Aside>
