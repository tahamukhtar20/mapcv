---
title: Migrating to 0.2
description: Update 0.1 configurations and datasets for mapcv 0.2.
---

## Move XYZ settings into `imagery`

```yaml
# 0.1 (deprecated)
region:
  west: 4.883
  south: 52.371
  east: 4.896
  north: 52.378
  zoom: 17
tiles:
  source: osm
```

```yaml
# 0.2
region:
  west: 4.883
  south: 52.371
  east: 4.896
  north: 52.378
imagery:
  type: xyz
  zoom: 17
  source: osm
```

The 0.1 shape still runs with a deprecation notice and will be removed in 0.3.0. `region.zoom` next to an `imagery` block is also deprecated: it fills a missing `imagery.zoom` and is otherwise ignored. `imagery.type` is required.

## Replace the Google preset

`google_satellite` is no longer built in, and configs that use it fail validation. If a provider explicitly authorizes automated XYZ access for your use case, configure its URL through `imagery.url_template` and follow its terms. Never commit credentials or signed URLs.

## Understand EOPF output

Install `mapcv[zarr]` and select `writer.image_format: npy`. EOPF patches use bands-first `(bands, height, width)` layout and decoded `float32` values. The configured band order is preserved.

## Manifest version 2

New manifests add source, product, band, dtype, patch shape, CRS, and affine-transform metadata. Rows and columns are global raster coordinates. Version 1 manifests remain readable by `mapcv split`, but 0.1.x datasets cannot be resumed by `mapcv generate` because their rows were per strip. Generate into a new `writer.staging_dir`.

Resuming requires the same imagery, labels, and sampler settings; a mismatch stops with an error. The manifest is saved after every chunk.

## Sampling changes

- `sampler.mode: random` now draws `random_count` patches in total, not per strip. Raise `random_count` to keep a similar dataset size.
- Grid patches can cross the old strip seams, and `edge_strategy` applies only at the raster's outer edges, so positions and counts can differ from 0.1.
- For XYZ, all-black pixels (including failed tiles under `lenient` or `ignore`) count as empty for `max_empty_ratio`.

## Splitting

The default `split.strategy` is now `spatial`: whole raster blocks go to one split and overlapping train/val patches are left out, so test scores are not inflated by leaked pixels. Use `strategy: stratified` or `random` for a patch-level split. 0.1 manifests need `split.block_size` for a spatial split.
