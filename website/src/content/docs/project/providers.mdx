## Imagery providers, licensing, and credentials

mapcv is software for processing imagery; it does not provide imagery or grant permission to download, cache, redistribute, or train models on provider data.

Before generating a dataset:

- review the provider's current terms, license, attribution requirements, quotas, and automated-access rules;
- use only an official endpoint and credentials you are authorized to use;
- keep API keys and signed URLs out of YAML, logs, manifests, examples, and source control;
- confirm that the resulting dataset and trained model may be stored, shared, and published for your use case.

The built-in XYZ names are conveniences, not endorsements or license guarantees. Free community tile servers are usually off-limits: the OpenStreetMap Foundation's servers, for example, forbid bulk downloading, so mapcv ships no OSM tile preset. OSM data itself is open (ODbL) and works well as labels. Custom XYZ URL templates remain supported, but mapcv never persists the template in the manifest. mapcv keeps downloaded XYZ tiles in an on-disk cache for as long as the server's caching headers allow (7 days when it sends none); set `imagery.cache: false` if the provider's terms do not allow local caching. EOPF URLs must be local or anonymously public and cannot include usernames, passwords, query strings, or fragments. Private-store authentication is intentionally not supported in 0.2.0.

## Practical notes by source

| Source | In mapcv | What to check |
| --- | --- | --- |
| Esri World Imagery, Topo, Street | `esri_satellite`, `esri_topo`, `esri_street` | Esri's terms of use and attribution for your use case (research, commercial, redistribution of derived data) |
| CARTO basemaps | `cartodb_positron`, `cartodb_dark_matter` | CARTO's basemap terms and attribution; these are rendered maps, not imagery |
| Your own or a commercial tile service | `url_template` | The contract for your key: bulk download, caching, ML training and redistribution are often treated separately |
| Copernicus Sentinel-2 (EOPF Zarr) | `type: eopf_zarr` | Free and open; credit "Contains modified Copernicus Sentinel data [year]" |
| OpenStreetMap data (as labels) | `labels.path` | ODbL: credit "© OpenStreetMap contributors"; sharing an adapted database has share-alike conditions |
| OpenStreetMap tile servers | not supported | The [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) forbids bulk downloading |
| Google imagery | not supported | mapcv cannot determine whether a use is licensed for downloading, caching or dataset creation ([details](/mapcv/project/migration/#google-imagery-preset)) |

## How mapcv helps you stay within the terms

- **No risky presets.** Presets for servers whose policies forbid bulk downloading were removed in 0.2; configs that still use them fail with an explanation.
- **Estimates before requests.** `mapcv plan` shows the number of tiles before anything is fetched, and large jobs need explicit confirmation.
- **Modest defaults in generated configs.** `mapcv init` writes `max_connections: 4`. mapcv retries with backoff, honours `Retry-After`, and sends a user agent that identifies mapcv and links to the project.
- **Secrets stay out of outputs.** The manifest records only `custom-xyz:<hostname>` for a custom template; `validate`, `plan` and `generate` print only the scheme and host; error messages strip query strings. See [Keep API keys out of YAML](/mapcv/guides/choose-imagery-and-zoom/#keep-api-keys-out-of-yaml).

None of this replaces reading the terms. If in doubt, ask the provider.
