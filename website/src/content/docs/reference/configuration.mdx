A mapcv config is one YAML file with six top-level blocks, an optional `task` and, for `task: detection`, `task: instance` or `task: classification`, an optional `detection`, `instance` or `classification` block. `region`, `imagery`, `sampler` and `writer` are required; `task`, `labels`, `detection`, `instance`, `classification` and `split` are optional. Unknown keys are errors, reported with their path (for example `sampler.stide: Extra inputs are not permitted`), so typos never pass silently. Relative paths (`labels.path`, `writer.staging_dir` and a local `imagery.path`) are resolved against the folder that contains the config file, so a config works from any working directory. `mapcv validate <file>` checks a config; `mapcv plan <file>` also reads the labels and estimates the run.

```yaml
task: segmentation  # what the dataset is for: segmentation (default), detection, instance or classification
region:   { … }   # where (required)
imagery:  { … }   # which pixels (required)
labels:   { … }   # which polygons or label raster (optional: omit for an image-only dataset)
detection: { … }  # box settings (optional, task: detection only)
instance: { … }   # mask settings (optional, task: instance only)
classification: { … }  # label rule (optional, task: classification only)
sampler:  { … }   # how to cut patches (required)
writer:   { … }   # where and how to write (required)
split:    { … }   # train/val/test lists (optional: omit to skip splitting)
```

## `task`

What the dataset is for. It decides what each patch is annotated with and is recorded in the manifest, so a resumed run must use the same task.

| Value | Status | Annotation |
| --- | --- | --- |
| `segmentation` (default) | supported | A class mask per patch, from `labels` (none without `labels`: an image-only dataset) |
| `detection` | supported | A box per object, written as COCO JSON and YOLO labels; needs `labels`. Settings in the [`detection`](#detection) block |
| `instance` | supported | A binary mask per object (instance segmentation), written as COCO JSON with RLE masks and optionally an instance-ID PNG per patch; needs vector `labels`. Settings in the [`instance`](#instance) block |
| `classification` | supported | One label, or a set of labels, per patch, written as `labels.csv` and `labels.json`; needs `labels` (vector or raster). Settings in the [`classification`](#classification) block |
| `change`, `regression` | planned | Rejected for now with an error that lists the supported and planned tasks |

```yaml
task: segmentation
```

## `detection`

Optional, and only allowed with `task: detection` (another task with a `detection` block is an error). Omit it for the defaults. One **object** is one label feature: a MultiPolygon is one object, and so is a feature that a patch edge cuts into pieces. Its box is the axis-aligned box of the part that is **visible** in the patch: inside the patch, inside the raster (not in padding) and over pixels with imagery. Holes do not change a box. Walkthrough: [Object detection datasets](/mapcv/tutorials/object-detection/); files: [Dataset format](/mapcv/reference/dataset-format/#detection-datasets).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `min_visible` | float, 0–1 | `0.3` | Keep an object in a patch only if at least this fraction of its area is visible there. `0` keeps every visible part; `1` keeps only whole objects. An object too large for any patch to show this fraction is never kept, and mapcv warns about it |
| `min_box_pixels` | float ≥ 0 | `2` | Drop boxes narrower **or** shorter than this many pixels (slivers along patch edges) |
| `formats` | list of `coco`, `yolo` | `[coco, yolo]` | Which annotation files to write. At least one; no duplicates |
| `point_box_size` | float > 0 \| `null` | `null` | Turn `Point`/`MultiPoint` features (not in KML) into square boxes of this many pixels, centred on the point. `null`: points are skipped with a warning, as for segmentation |

```yaml
task: detection
labels:
  path: buildings.geojson
  label_field: class
detection:
  min_visible: 0.3
  min_box_pixels: 2
  formats: [coco, yolo]
```

**Validation** (with `task: detection`): `labels` is required; `labels.ignore_index`, `labels.all_touched` and `writer.mask_format` are mask settings and are rejected when set, as is `writer.world_files` with images that are not PNG or JPG; `point_box_size` needs point labels from GeoJSON, GeoPackage, Shapefile or GeoParquet (KML points are not read); `sampler.pad_mode: reflect` is rejected with `edge_strategy: pad`, because mirrored padding would show objects without boxes. `sampler.min_label_ratio` keeps a patch only when its boxes' visible areas (overlaps counted once) cover at least that fraction of it. Detection writes no masks. A resumed run must use the same `detection` settings.

## `instance`

Optional, and only allowed with `task: instance` (another task with an `instance` block is an error). Omit it for the defaults. One **instance** is one label feature: a MultiPolygon is one instance, and so is a feature that a patch edge cuts into pieces. Its mask is the part of the feature that is **visible** in the patch: inside the patch, inside the raster (not in padding) and over pixels with imagery. Every instance is burned on its own with the same rasterizer and pixel rule as segmentation masks (`labels.all_touched` applies), so overlapping instances each keep their exact mask. Walkthrough: [Instance segmentation datasets](/mapcv/tutorials/instance-segmentation/); files: [Dataset format](/mapcv/reference/dataset-format/#instance-segmentation-datasets).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `min_visible` | float, 0–1 | `0.3` | Keep an instance in a patch only if at least this fraction of its area is visible there. `0` keeps every visible part; `1` keeps only whole instances. A feature too large for any patch to show this fraction is never kept, and mapcv warns about it |
| `min_area` | int ≥ 1 | `4` | Drop instances whose mask has fewer pixels than this (slivers along patch edges, features smaller than a pixel) |
| `id_mask` | bool | `false` | Also write one 16-bit instance-ID PNG per patch to `masks/` (`writer.mask_format` then sets its format). A patch with more than 65,535 instances is an error |

```yaml
task: instance
labels:
  path: buildings.geojson
  label_field: class
instance:
  min_visible: 0.3
  min_area: 4
  id_mask: false
```

**Validation** (with `task: instance`): `labels` is required and must be vector labels (a label raster has no objects; use `task: segmentation`); `labels.ignore_index` is rejected when set (instance masks only hold pixels that have imagery); `writer.mask_format` is rejected unless `instance.id_mask` is on; `writer.world_files` is rejected with images that are not PNG or JPG unless `id_mask` is on; `sampler.pad_mode: reflect` is rejected with `edge_strategy: pad`, because mirrored padding would show objects without masks. `sampler.min_label_ratio` keeps a patch only when its instances (overlaps counted once) cover at least that fraction of it. A resumed run must use the same `instance` settings and `labels.all_touched`.

## `classification`

Optional, and only allowed with `task: classification` (another task with a `classification` block is an error). Omit it for the defaults. A patch's label comes from how much of it each class covers. **Coverage** is a class's pixels divided by the patch's **valid** pixels, counted on the very mask that segmentation would write for the same `labels` (the same rasterizer and pixel rule for polygons, `labels.all_touched` included; the same nearest-neighbour sampling for a label raster). A pixel is valid when it has imagery (inside the raster, not NoData or a failed tile) and is not `labels.ignore_index`; for a label raster that includes pixels outside the label raster, on its NoData and on `labels.ignore_values`. Background (mask value 0) is not a class and has no coverage. Where polygons overlap, the mask's later-wins rule applies: the later feature's class takes the shared pixels. Coverage is computed as `pixels / valid pixels` in 64-bit floating point. (With a label raster and `labels.ignore_index: null`, pixels without a label become background in the mask and so stay in the denominator; only pixels without imagery are left out.) Walkthrough: [Patch classification datasets](/mapcv/tutorials/classification/); files: [Dataset format](/mapcv/reference/dataset-format/#classification-datasets).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `single` \| `multi` | `single` | `single`: the patch gets the class with the largest coverage (a tie goes to the lowest class ID), if that class qualifies. `multi`: the patch gets every class that qualifies, in ascending class ID order (a multi-hot label) |
| `min_fraction` | float, 0–1 | `0.0` | A class qualifies when its coverage is **at least** this and above zero, so `0` means "any labeled pixel". `0.5` with `single` is a strict majority rule |
| `empty` | `skip` \| `background` | `skip` | What happens to a patch no class qualifies for. `skip` drops it (it is not written); `background` keeps it with the label `background` (class ID 0). A patch without a single valid pixel is always dropped, because there is nothing to judge; `sampler.max_empty_ratio` drops patches that are mostly without imagery |

```yaml
task: classification
labels:
  path: landuse.geojson
  label_field: class
classification:
  mode: multi
  min_fraction: 0.1
  empty: background
```

**Validation** (with `task: classification`): `labels` is required, vector or `type: raster`; `writer.mask_format` is rejected (no masks are written), as is `writer.world_files` with images that are not PNG or JPG; `sampler.pad_mode: reflect` is rejected with `edge_strategy: pad`, because the mirrored part of an edge patch would show imagery that no label counts; `sampler.min_label_ratio` greater than 0 is rejected with `empty: background`, because it would drop exactly the background patches (without `background`, it keeps its segmentation meaning: the labeled share of the whole patch must reach it). Class names must not hold control characters, and with `mode: multi` no whitespace, because a patch's labels are joined with a space in `labels.csv`; with `empty: background` no class may be named `background`. A resumed run must use the same `classification` settings and `labels.all_touched`.

## `region`

The area of interest as a WGS-84 longitude/latitude bounding box.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `west` | float | required | Western longitude in degrees |
| `south` | float | required | Southern latitude in degrees |
| `east` | float | required | Eastern longitude in degrees |
| `north` | float | required | Northern latitude in degrees |

**Validation:** longitudes in −180…180, latitudes in −90…90, `west < east` and `south < north`. With XYZ imagery the box must also stay within ±85.0511° latitude, the limit of Web Mercator tiles. A box that crosses the antimeridian is not supported. `region.zoom` from the 0.1 layout was removed in 0.3.0; set `imagery.zoom` instead (see [Removed 0.1 keys](#removed-01-keys)).

For XYZ imagery the box is expanded outward to whole tiles at the chosen zoom. For Sentinel-2 it is reprojected into the product's CRS and expanded outward to the product's pixel edges. For a GeoTIFF it is reprojected into the file's CRS, expanded outward to the file's pixels and clipped to the raster. See [Coordinates and grids](/mapcv/concepts/coordinates-and-grids/).

## `imagery`

Selects an imagery source with the required `type` key: `xyz`, `eopf_zarr` or `geotiff`. For segmentation datasets it can also be a list of named sources ([several sources](#several-imagery-sources)).

### Several imagery sources

Write `imagery` as a list to sample several sources at the same patches: a before/after pair, optical plus a DEM, or two dates of the same product. Every source in the list needs a `name`. Each source keeps its own settings.

```yaml
imagery:
  - {type: geotiff, name: before, path: 2023.tif}
  - {type: geotiff, name: after, path: 2025.tif}
  - {type: geotiff, name: dem, path: dem_2m.tif}    # pixels twice as large: repeated
writer: {staging_dir: ./dataset, image_format: tif}
```

| Rule | Detail |
| --- | --- |
| Names | 1–32 lowercase letters, digits, `_` or `-`, unique. `mask` and names ending in `_world` are reserved |
| Grid | The **first** source's pixel grid is the dataset's grid; region, patches, masks and georeferencing all follow it |
| Other sources | Same CRS as the first, and pixels the same size or a whole number of them across (2×, 3×…) on a grid that shares pixel corners with the first. Coarser pixels are repeated onto the grid (nearest neighbour, exact); nothing is interpolated. A source with finer pixels must come first |
| Coverage | A pixel has imagery only where **every** source has it. Pixels outside a source count as empty and are `ignore_index` in masks |
| Output | `Images/<name>/patch_*.<ext>` per source, one shared `Masks/` folder, and one `files` key per source name in the manifest |
| Tasks | `segmentation` (with or without labels). Tasks that write one image per patch (detection, instance, classification) take a single source |

A source on a grid that does not line up (another CRS, a half-pixel shift, a non-integer pixel ratio) fails before anything is written, and the error says how it differs. Resample it onto the first source's grid first (for example with `gdalwarp -tap -tr`).

### XYZ tiles (`type: xyz`)

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `"xyz"` | required | Selects XYZ tiles |
| `zoom` | int, 1–22 | required | Tile zoom level. Pixel size ≈ 156 543 × cos(latitude) / 2<sup>zoom</sup> m |
| `source` | string | — | A built-in source: `esri_satellite`, `esri_topo`, `esri_street`, `cartodb_positron`, `cartodb_dark_matter` |
| `url_template` | string | — | Your own `http://` or `https://` URL with `{z}`, `{x}` and `{y}` |
| `max_connections` | int ≥ 1 | `16` | Concurrent tile requests. Keep this low for shared servers; `mapcv init` writes `4` |
| `policy` | `strict` \| `lenient` \| `ignore` | `lenient` | What happens to a tile that still fails after retries (see below) |
| `max_failed_ratio` | float, 0–1 | `0.05` | Under `lenient`, the run stops if more than this fraction of a chunk's tiles fail |
| `strip_rows` | int ≥ 1 | `4` | Tile rows per processing chunk (4 rows = 1,024 px). Lower it to reduce memory on very wide regions |

**Validation:**

- Exactly one of `source` or `url_template` is required; setting both is an error.
- `source` must be a built-in name. The 0.1 presets `google_satellite` and `osm` were removed and fail with an explanation ([why](/mapcv/project/migration/#google-imagery-preset)).
- `url_template` must be `http(s)`, must contain `{x}`, `{y}` and `{z}`, and may contain no other placeholder. A `{s}` subdomain placeholder is rejected: replace it with one subdomain, for example `a`.
- Tiles must decode to 256 × 256 images (PNG, JPEG, WebP or GIF).
- `writer.image_format` must be `png`, `jpg` or `tif`.

**Failure policy.** Each tile is tried up to four times (three retries with backoff that honours `Retry-After` up to 30 s). Connection errors, timeouts, truncated bodies, HTTP 429 and 5xx are retried; other 4xx responses and non-image bodies (for example an HTML error page) fail immediately. A tile that still fails is then handled by `policy`:

| `policy` | Failed tile | `max_failed_ratio` |
| --- | --- | --- |
| `strict` | Stops the run with an error | not used |
| `lenient` | Left out; its pixels are black and count as empty | enforced per chunk |
| `ignore` | Filled with a black tile | never enforced |

Requests identify themselves with the user agent `mapcv/<version> (+https://github.com/tahamukhtar20/mapcv)`.

<Aside type="caution">
Built-in names are conveniences, not licences. Check the provider's terms before downloading; see [Providers & licensing](/mapcv/project/providers/). Keep API keys out of committed YAML: mapcv never writes `url_template` into the manifest, but your config file is your responsibility.
</Aside>

### Sentinel-2 L2A EOPF Zarr (`type: eopf_zarr`)

Requires `pip install "mapcv[zarr]"` (Python 3.10–3.13).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `"eopf_zarr"` | required | Selects one EOPF Sentinel-2 L2A product |
| `path` | string | required | Local path, `file://` URL, or anonymous `https://` or `s3://` URL of the `.zarr` product. A relative local path is resolved against the config file's folder |
| `resolution` | `10` \| `20` \| `60` | `10` | Output grid in metres; every band is harmonised onto it |
| `bands` | list of strings | all 12 | Variables to read, **in output order**. Default: `b01 b02 b03 b04 b05 b06 b07 b08 b8a b09 b11 b12` |
| `chunk_rows` | int ≥ 1 | `1024` | Raster rows per processing chunk |

**Validation:**

- `path` may not contain a username, password, query string or fragment; private-store authentication is not supported. Windows paths (`C:\data\S2.zarr`, `file:///C:/data/S2.zarr`) work.
- `bands` must be non-empty and without duplicates; names are lower-cased (`B04` → `b04`). Unknown band names fail when the product is opened, with a list of what is available.
- `writer.image_format` must be `npy` or `tif`.
- The region must intersect the product.

### GeoTIFF and Cloud Optimized GeoTIFF (`type: geotiff`)

Needs no extra install. Reads one file as it is: patches keep the file's CRS, pixel grid, band count and data type, and nothing is resampled. A guide with examples: [Use your own GeoTIFF](/mapcv/guides/use-your-own-geotiff/).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `"geotiff"` | required | Selects one GeoTIFF or COG |
| `path` | string | required | Local path, `file://` URL, or `https://` or anonymous `s3://` URL (read with HTTP range requests). A relative local path is resolved against the config file's folder |
| `bands` | list of ints ≥ 1 | all bands | **1-based** band numbers to read, **in output order**: `[3, 2, 1]` reverses the bands of a BGR file. Band names in the manifest keep the file's numbering (`b3`, `b2`, `b1`) |
| `overview` | int ≥ 0 | `0` | Overview level: `0` is the full resolution, `1` the first (largest) overview, and so on. Fails when the file has fewer levels |
| `nodata` | number \| `.nan` | file's value | NoData value that overrides (or supplies) the file's. Pixels where every selected band equals it have no imagery |
| `chunk_rows` | int ≥ 1 | `1024` | Raster rows per processing chunk |

**Validation:**

- `path` may not contain a username, password, query string or fragment; private-store authentication is not supported. Plain `http://` is accepted only for a loopback host (`localhost`, `127.0.0.1`), for a local test server. Windows paths work.
- `bands` must be non-empty and without duplicates.
- The file must have a CRS that is an EPSG code and a pixel transform, and its compression must be one the reader supports (none, Deflate, LZW, PackBits, ZSTD, JPEG, WebP); the error names the problem. The region must intersect the file.
- `writer.image_format`: `png` or `jpg` need `uint8` data in **1 or 3** selected bands (a single band is written as gray, repeated into three channels); any other data type or band count needs `npy` or `tif` (both keep the file's data type and band count; `tif` also writes georeferenced patches). A selection that cannot fit PNG/JPG is rejected when the config is loaded; the data type is checked when the file is opened (`mapcv plan` does that, without reading pixels).

**Empty pixels.** A pixel has no imagery when every selected band equals the NoData value, or, for floating-point files, is `NaN` or infinite. They count as empty for `sampler.max_empty_ratio` and are `labels.ignore_index` in masks, like the area outside the raster. A region that extends beyond the file is clipped to it with a warning; one that misses it is an error.

**Resuming.** The manifest records a fingerprint of the file in `sources[0].fingerprint` and a resumed run refuses a different file (see [Dataset format](/mapcv/reference/dataset-format/#sources)).

## `labels`

Optional. Without it you get an image-only dataset (no `Masks/`). `labels.type` picks where the masks come from: `vector` (the default, so configs without `type` keep working) burns polygons from a GeoJSON, KML, GeoPackage, Shapefile or GeoParquet file; `raster` reads a classified GeoTIFF, see [Raster labels](#raster-labels-type-raster).

### Polygon labels (`type: vector`)

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `vector` | `vector` | Polygon labels |
| `path` | path | required | A `.geojson`, `.json`, `.kml`, `.gpkg`, `.shp`, `.parquet` or `.geoparquet` file. GeoJSON and KML are WGS-84 longitude/latitude; the others may use any CRS they state and are reprojected. A relative path is resolved against the config file's folder |
| `layer` | string \| null | `null` | GeoPackage only: the layer (table) to read. Required when the file has several; leave unset with one. An error for other formats |
| `label_field` | string \| null | `null` | Feature property (GeoJSON, KML) or column (the other formats) holding the class. `null`: every polygon is class `1` |
| `classes` | map label → int | `null` | Fixed class IDs, each 1–255, for example `{building: 1, road: 2}`. Requires `label_field`. Labels not in the map are skipped |
| `ignore_index` | int 1–255 or `null` | `255` | Mask value for pixels with no imagery under them: padding, failed tiles and NoData. Pass it to your loss (`CrossEntropyLoss(ignore_index=255)`). No class may use it; `null` writes background (`0`) there instead. With `task: classification` no mask is written and imagery-less pixels never count either way |
| `all_touched` | bool | `false` | Burn every pixel a polygon touches, not only pixels whose centre is inside |

**How class IDs are chosen** (`label_field` set, no `classes`): if every label is an integer from 1 to 255, the integer is the ID; otherwise the distinct labels are sorted and numbered 1, 2, 3, …. `3` and `3.0` are the same class. More than 255 distinct labels is an error. Features without polygon geometry or without a label value are skipped with a warning that counts them. Where polygons overlap, the one later in the file wins.

**Validation:** suffix must be one of the above (unzip a KMZ to its KML first; a `.tif` asks for `type: raster`); `layer` needs a `.gpkg`; `classes` keys must be non-empty and values integers in 1–255; `classes` requires `label_field`. GeoJSON with a projected `crs` member is rejected. At run time a Shapefile without `.prj`, a layer without a CRS and a GeoParquet file with `crs: null` are errors (the CRS would be a guess), GeoParquet needs `pip install "mapcv[parquet]"`, and a `label_field` that is not a column of the table lists the columns. The manifest records `layer` in `target.labels` when it is set. Details: [Prepare labels](/mapcv/guides/prepare-labels/).

### Raster labels (`type: raster`)

A classified raster, such as a land-cover map (ESA WorldCover, Dynamic World), a national map or an earlier model's output, used as the masks. It may have any CRS, resolution and origin: mapcv reads it on the imagery's pixel grid.

```yaml
labels:
  type: raster
  path: ESA_WorldCover_10m_2021_v200_N48E000_Map.tif   # local, https:// or anonymous s3://
  classes:                    # raster value -> mask ID, or -> {id, name}
    10: {id: 1, name: tree_cover}
    30: {id: 2, name: grassland}
    40: {id: 3, name: cropland}
    50: {id: 4, name: built_up}
    80: {id: 5, name: water}
    90: {id: 6, name: wetland}
    95: {id: 6, name: wetland}  # several values may share an ID
  unmapped: background        # other values: background | ignore
```

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `raster` | required | Raster labels |
| `path` | string | required | A GeoTIFF or COG: a local path (relative to the config file's folder), an `https://` URL or an anonymous `s3://bucket/key`, read like [GeoTIFF imagery](#geotiff-and-cloud-optimized-geotiff-type-geotiff) (only the tiles under each window). Its CRS must be an EPSG code and its values integers (`uint8`, `uint16`, `int16`, …) |
| `band` | int ≥ 1 | `1` | Band holding the classes (1-based) |
| `classes` | map value → ID or `{id, name}` | required | Raster value → mask ID (0–255, `0` is background). The short form `10: 1` names the class `value_10` (`value_90_95` when several values share the ID); `{id: 1, name: tree_cover}` names it. One ID has one name. The names and IDs are the manifest's `class_map` |
| `unmapped` | `background` \| `ignore` | `background` | What values missing from `classes` become: background (`0`), or `ignore_index` |
| `nodata` | int \| null | the file's NoData | Label value meaning "no label": such pixels get `ignore_index` |
| `ignore_values` | list of int | `[]` | More label values that get `ignore_index` (for example "unclassified") |
| `resampling` | `nearest` | `nearest` | How a label pixel is picked; categorical values are never averaged, so `nearest` is the only choice |
| `ignore_index` | int 1–255 or `null` | `255` | As for polygon labels; it also marks pixels outside the label raster, label NoData and `ignore_values`. `null` writes background (`0`) there |

**Alignment.** Each imagery pixel takes the value of the label pixel that contains the imagery pixel's **centre**. The centre (`col + 0.5`, `row + 0.5` in the corner-based affine transform) is projected exactly into the label raster's CRS (pyproj; computed in parallel threads, with exactly the coordinates a call per point gives), then the inverse of the label raster's transform gives a fractional label pixel, which is rounded down (`floor(x + 1e-10)`: a centre exactly on a boundary between two label pixels takes the right / lower one, as GDAL does). Files tagged `PixelIsPoint` are shifted by half a pixel to corner-based, as in GDAL. The result equals `rasterio.warp.reproject(..., resampling=Resampling.nearest, tolerance=0)` onto the patch's transform. (GDAL's default `tolerance=0.125` approximates the transformation and can pick a neighbouring label pixel near boundaries.) When the label raster shares the imagery's CRS and pixel grid, windows are copied directly, with the same result.

**Validation:** `classes` must list at least one value; no ID may be `ignore_index`; an ID has one name and a name one ID; ID `0` takes no name; `ignore_values` and `nodata` may not be in `classes`; `unmapped: ignore` needs an `ignore_index`. Raster labels make masks, so they work with `task: segmentation` and, for one label per patch, `task: classification`; `task: detection` and `task: instance` need polygon labels (one feature per object) and refuse `type: raster`. `generate` and `plan` refuse a label raster without an EPSG CRS, with non-integer values or without the configured band, and warn when it does not overlap the imagery. Details: [Prepare labels](/mapcv/guides/prepare-labels/#use-a-classified-raster-as-labels).

## `sampler`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `patch_size` | int > 0 | required | Side of each square patch in pixels |
| `stride` | int ≥ 0 | `0` | Step between grid patches. `0` means `patch_size` (no overlap); smaller values overlap |
| `mode` | `grid` \| `random` | `grid` | Regular grid, or `random_count` random positions |
| `edge_strategy` | `pad` \| `drop` \| `shift` | `pad` | What to do where a patch would cross the raster edge (see below) |
| `pad_mode` | `zero` \| `reflect` | `zero` | How `pad` fills the missing part of an edge patch |
| `max_empty_ratio` | float, 0–1 | `1.0` | Skip patches whose empty fraction is **above** this. `1.0` keeps everything |
| `min_label_ratio` | float, 0–1 | `0.0` | Skip patches whose labeled (non-zero mask) fraction is **below** this. Only applies with labels. For detection, the labeled fraction is the area of the kept objects' visible parts; for classification, the valid pixels of any class over the whole patch |
| `random_seed` | int ≥ 0 | `42` | Seed for `mode: random` |
| `random_count` | int ≥ 0 | `100` | Number of random patches **in total** (not per chunk). Capped at the number of distinct positions on the raster (a warning says so) |

**Edge strategies:**

| `edge_strategy` | Grid behaviour | Random behaviour |
| --- | --- | --- |
| `pad` | Patches start at every stride step inside the raster; the part outside is filled by `pad_mode` and the patch is marked `padded` | Same positions as `drop`; a raster smaller than the patch gives one padded patch at the top-left |
| `drop` | Only patches that fit entirely inside | Positions where the patch fits entirely inside; none if the raster is smaller than the patch |
| `shift` | Like `drop`, plus one last patch shifted inward to cover the remaining edge (may overlap its neighbour) | Same as `pad` |

**Empty pixels:** for GeoTIFF, a pixel is empty when it is outside the file, equal to NoData in every selected band, or non-finite (floating-point files). For XYZ, a pixel is empty when all three channels are 0 (black tiles, failed tiles, padding). For Sentinel-2, a pixel is empty unless every band has data, i.e. when any band is NaN (NoData); a reflectance of 0 is valid data. Padding in Sentinel-2 patches is 0, not NaN.

<Aside>
Random mode draws distinct positions, uniformly over every position where the patch fits (the raster edges are sampled as often as the centre), and the same seed always gives the same positions. If `random_count` is more than the number of positions, all of them are used and mapcv warns. Random patches can still overlap each other. Use the `spatial` split with it (the default); mapcv warns if you choose `stratified` or `random`.
</Aside>

## `writer`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `staging_dir` | path | required | Output folder, created if needed; a relative path is resolved against the config file's folder. Re-running into a folder with a compatible `manifest.json` resumes |
| `image_format` | `png` \| `jpg` \| `npy` \| `tif` | `png` | `png`/`jpg` for XYZ (RGB `uint8`); `npy` for Sentinel-2 (bands-first `float32`); `tif` for any source: a georeferenced GeoTIFF with the source's own band count and data type. For GeoTIFF imagery `png`/`jpg` need `uint8` in 1 or 3 bands, otherwise use `npy` (bands-first, the file's data type) or `tif` |
| `jpg_quality` | int, 1–100 | `95` | JPEG quality when `image_format: jpg` |
| `jpg_subsampling` | `4:2:0` \| `4:4:4` | `4:2:0` | JPEG chroma subsampling when `image_format: jpg`. `4:2:0` stores colour at half resolution in each direction, like Pillow's default, and gives smaller files (about 10% on typical aerial imagery at quality 95, up to half on noisy colour imagery). Use `4:4:4` to keep full colour resolution. JPEG datasets made by mapcv 0.2 are `4:4:4`, so resume them with `jpg_subsampling: 4:4:4` |
| `mask_format` | `png` \| `npy` \| `tif` | `png` | How masks are stored (with `labels`). `png` is a single-channel PNG (8-bit; 16-bit for 16-bit masks); `npy` a NumPy array; `tif` a GeoTIFF that opens aligned with the image. The mask values, including `labels.ignore_index`, are identical in every format |
| `world_files` | bool | `false` | Write a world file next to every PNG (`.pgw`) and JPG (`.jgw`) patch, images and masks, so QGIS and GDAL place them on the map. World files hold no CRS (it is `crs` in the manifest). Not needed for `tif`, which carries its georeferencing inside; an error when neither images nor masks are PNG or JPG |
| `footprints` | bool | `true` | Write `patches.geojson` after the split: one WGS-84 footprint polygon per patch with its file name, split, row and column, and class pixel counts. Open it in QGIS to see where each patch is. Needs `pyproj` (`pip install "mapcv[zarr]"`) unless the imagery is XYZ or EPSG:4326; without it mapcv warns and skips the file |

The manifest records the writer as `{layout: files, image_format, jpg_quality, jpg_subsampling, mask_format}` (plus `world_files: true` when it is on). Changing `image_format`, `mask_format` or `world_files` of an existing dataset is a configuration mismatch, so resuming it is refused; `footprints` does not affect the patches and may change. Layout and naming: [Dataset format](/mapcv/reference/dataset-format/). Detection and classification datasets record no `mask_format` (setting it is an error: they write no masks) and write images to `images/` (lowercase, where Ultralytics looks for them) instead of `Images/`; Ultralytics reads PNG, JPG and TIF images, not NPY.

**GeoTIFF output.** `tif` patches (and masks) are written by mapcv itself, without GDAL: striped, Deflate-compressed with the horizontal predictor (the floating-point predictor for `float32`), one band per channel. They carry the source's EPSG code and each patch's own affine transform, so QGIS, rasterio and TerraTorch open them in place. Images declare `NaN` as no-data when they are floating point (and nothing for integer data, where 0 is a real value); masks declare `labels.ignore_index` as no-data, so GIS tools show the pixels without imagery as transparent. See [Dataset format](/mapcv/reference/dataset-format/#geotiff-patches).

**Validation:** XYZ needs `png`, `jpg` or `tif`; EOPF needs `npy` or `tif`; GeoTIFF imagery needs `npy` or `tif` unless it is `uint8` in 1 or 3 bands (see [GeoTIFF](#geotiff-and-cloud-optimized-geotiff-type-geotiff)). `world_files` needs PNG or JPG files to write next to.

## `split`

Optional. When present, `mapcv generate` writes split lists at the end; `mapcv split` can redo them later with different settings.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `strategy` | `spatial` \| `stratified` \| `random` | `spatial` | `spatial` assigns whole raster blocks to one split and drops train/val patches overlapping a held-out patch. `stratified` and `random` split individual patches |
| `test_ratio` | float, 0–1 | `0.20` | Fraction of patches for `test.txt` |
| `val_ratio` | float, 0–1 | `0.10` | Fraction of the **remaining** patches for `val.txt` |
| `block_size` | int ≥ 1 | auto | `spatial` block side in pixels. Default 4 × `patch_size`, reduced (never below `patch_size`) so the raster has at least 10 blocks |
| `labeled_ratios` | list of floats in (0, 1] | `[0.10, 0.20, 0.30]` | Write `splits/<percent>/labeled.txt` and `unlabeled.txt` subsets of train for each ratio. `[]` writes none |
| `seed` | int | `42` | Seed for shuffling blocks or patches |
| `sample_limit` | int ≥ 1 | — | Split only this many patches (subsampled, keeping the stratum mix unless `strategy: random`) |

**Validation:** ratios within bounds; `labeled_ratios` may not contain duplicates (after conversion to folder names such as `0.125` → `12.5`). With `spatial`, the achieved ratios are approximate because whole blocks move together. See [Splits without leakage](/mapcv/guides/splits-without-leakage/).

## Removed 0.1 keys

mapcv 0.2 still loaded the 0.1 layout (`region.zoom` plus a top-level `tiles:` block) with a deprecation notice. Both were removed in 0.3.0 and now fail validation, with the replacement named in the error:

```console
$ mapcv validate old.yaml
Config error in old.yaml:
  • config: `tiles:` was replaced by `imagery:` in mapcv 0.2 and removed in 0.3; move it under `imagery: {type: xyz, zoom: ..., source: ...}` and delete `region.zoom` (see MIGRATION.md)
```

| Removed | Use instead |
| --- | --- |
| `region.zoom` | `imagery.zoom` |
| `tiles:` | `imagery: {type: xyz, zoom: …, source: …}` |

Full guide: [Migrating to 0.2](/mapcv/project/migration/).
