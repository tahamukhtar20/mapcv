This tutorial builds an **object detection** dataset from the [quickstart](/mapcv/quickstart/) data: Esri World Imagery over Amsterdam's Eastern Docklands at about 0.36 m per pixel, with every OpenStreetMap building as a box. mapcv writes the boxes twice, as COCO JSON and as YOLO text files, so the same folder trains with Ultralytics, torchvision, Detectron2 or MMDetection.

**Time:** about 15 minutes. **You need:** `pip install mapcv`; `ultralytics` or `torch` + `torchvision` for the training step.

<Steps>

1. ### Get the labels

   The labels are the quickstart's building outlines (967 features, each with `class: building`):

   ```bash
   mkdir docklands-boxes && cd docklands-boxes
   curl -LO https://raw.githubusercontent.com/tahamukhtar20/mapcv/main/examples/quickstart/buildings.geojson
   ```

   OSM data is © OpenStreetMap contributors under the ODbL, which asks you to credit it when you share the result.

2. ### Write the config

   It is the quickstart config plus `task: detection` and an optional `detection` block. `mapcv init --template detection` writes the same file with comments.

   ```yaml title="mapcv.yaml" {1,19-22}
   task: detection

   region:
     west: 4.9375
     south: 52.3725
     east: 4.9515
     north: 52.3780

   imagery:
     type: xyz
     zoom: 18                   # ≈ 0.36 m/px at this latitude
     source: esri_satellite
     max_connections: 4

   labels:
     path: buildings.geojson
     label_field: class         # one class: building

   detection:
     min_visible: 0.3           # keep a building in a patch if ≥ 30% of it is visible there
     min_box_pixels: 2          # drop slivers narrower or shorter than 2 px
     formats: [coco, yolo]

   sampler:
     patch_size: 256
     edge_strategy: drop

   writer:
     staging_dir: ./dataset
     image_format: png

   split:
     strategy: spatial          # whole blocks per split: no leakage between splits
     test_ratio: 0.20
     val_ratio: 0.10
     seed: 42
   ```

   How a building becomes a box:

   - **One feature, one object.** Each GeoJSON feature is one object, including a MultiPolygon. A building cut by a patch edge is still one object; its box covers the part inside the patch.
   - **Only what is visible.** The box surrounds the part of the building that the patch shows: inside the patch, inside the raster, and over pixels that have imagery (failed tiles and NoData are cut out). Courtyards (holes) do not change the box.
   - **`min_visible`** decides whether a building that the patch shows only in part gets a box there. With `0.3`, a building split 50/50 between two patches gets a box in both, and one with 20% in a patch gets none in that patch. Boxes of cut buildings are flagged `truncated` in COCO.
   - **`min_box_pixels`** removes thin slivers along patch edges.

   All options: [Configuration → detection](/mapcv/reference/configuration/#detection).

5. ### Look at the boxes

   COCO boxes are `[x, y, width, height]` in pixels from the patch's top-left corner:

   ```python title="look.py"
   import json

   import matplotlib.patches as patches
   import matplotlib.pyplot as plt
   from PIL import Image

   coco = json.load(open("dataset/annotations/instances_train.json"))
   images = coco["images"][:4]
   fig, axes = plt.subplots(1, len(images), figsize=(4 * len(images), 4))
   for ax, image in zip(axes, images):
       ax.imshow(Image.open(f"dataset/images/{image['file_name']}"))
       for ann in coco["annotations"]:
           if ann["image_id"] == image["id"]:
               x, y, w, h = ann["bbox"]
               color = "orange" if ann["truncated"] else "lime"
               ax.add_patch(patches.Rectangle((x, y), w, h, fill=False, color=color))
       ax.set_title(image["file_name"])
       ax.axis("off")
   plt.tight_layout()
   plt.show()
   ```

   Boxes should frame roofs; orange ones are buildings cut by the patch edge. Footprints are drawn on other imagery, so tall buildings can look shifted (the photo shows them leaning).

6. ### Train a detector

   **Ultralytics YOLO** reads `dataset.yaml`, which points at the image lists and names the classes (`0: building`):

   ```bash
   pip install ultralytics
   yolo detect train data=dataset/dataset.yaml model=yolo11n.pt imgsz=256 epochs=50
   ```

   or from Python:

   ```python
   from ultralytics import YOLO

   model = YOLO("yolo11n.pt")
   model.train(data="dataset/dataset.yaml", imgsz=256, epochs=50)
   metrics = model.val(split="test")
   ```

   `dataset.yaml` has no `path:` key, so Ultralytics resolves the image lists against the folder the file is in: copy the whole `dataset/` folder to a GPU machine and train there without editing anything.

   **torchvision** reads the COCO files. This dataset class turns them into what torchvision's detection models expect (boxes as `[x1, y1, x2, y2]`, class IDs as labels, and an empty box list for background patches):

   ```python title="train_frcnn.py"
   import json

   import torch
   import torchvision
   from PIL import Image
   from torchvision.transforms.functional import to_tensor


   class CocoBoxes(torch.utils.data.Dataset):
       def __init__(self, root, split):
           coco = json.load(open(f"{root}/annotations/instances_{split}.json"))
           self.root, self.images = root, coco["images"]
           self.boxes = {image["id"]: [] for image in self.images}
           for ann in coco["annotations"]:
               self.boxes[ann["image_id"]].append(ann)

       def __len__(self):
           return len(self.images)

       def __getitem__(self, index):
           image = self.images[index]
           anns = self.boxes[image["id"]]
           boxes = [[x, y, x + w, y + h] for x, y, w, h in (ann["bbox"] for ann in anns)]
           target = {
               "boxes": torch.tensor(boxes, dtype=torch.float32).reshape(-1, 4),
               "labels": torch.tensor([ann["category_id"] for ann in anns], dtype=torch.int64),
           }
           pixels = Image.open(f"{self.root}/images/{image['file_name']}").convert("RGB")
           return to_tensor(pixels), target


   train = CocoBoxes("dataset", "train")
   loader = torch.utils.data.DataLoader(
       train, batch_size=8, shuffle=True, collate_fn=lambda batch: tuple(zip(*batch))
   )
   # num_classes counts the background: 1 building class + 1.
   model = torchvision.models.detection.fasterrcnn_resnet50_fpn(
       weights=None, weights_backbone="DEFAULT", num_classes=2
   )
   optimizer = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9, weight_decay=1e-4)
   model.train()
   for epoch in range(20):
       for images, targets in loader:
           losses = model(list(images), list(targets))
           loss = sum(losses.values())
           optimizer.zero_grad()
           loss.backward()
           optimizer.step()
       print(epoch, float(loss))
   ```

   For COCO-style mAP on the test split, run the model on `instances_test.json`'s images and score the results with `pycocotools.cocoeval.COCOeval`; the `area` of each annotation is the building's visible area, which COCO uses for its small/medium/large breakdown.

7. ### Variations

   - **Several classes.** Set `label_field: building` (the OSM tag: `house`, `apartments`, …) and a new `staging_dir`. COCO `category_id` is the class ID that `mapcv plan` prints; YOLO indices are the same classes counted from 0 in ID order.
   - **Points.** For point labels (trees, cars, wells), set `detection.point_box_size` to a box side in pixels: each GeoJSON point becomes a square box centred on it.
   - **Only one format.** `formats: [yolo]` or `formats: [coco]`.
   - **Large objects.** A field or lake larger than a patch can never show 30% of itself in one patch; mapcv warns about such features. Lower `min_visible`, or use larger patches.

</Steps>

<Aside type="caution">
A dataset's detection settings are part of it: resuming with a different `min_visible`, `min_box_pixels`, `formats` or `point_box_size` is refused. Write to a new `staging_dir` instead. `mapcv split` re-splits a finished dataset and rewrites the COCO files, image lists and `dataset.yaml`, keeping every image and annotation ID.
</Aside>
